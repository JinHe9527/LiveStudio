# 直播主机部署前检查：v0.1.29

2026-09-14，基于 main / c1d629c 和本机安装版 0.1.29。仅检查代码、进程计数器和现有存档的隔离 Excel 导出，未修改 OBS/直播伴侣配置、触发恢复、删除存档或改变云端/局域网设置。

## 删除和配置写入范围

检查本机删除、临时清理与事务目录调用，未发现全盘搜索清理或无关目录批量删除逻辑。存档删除入口需界面确认；执行端只接受受管存档目录内的 `.lscfg` 路径，先移到临时名称再删除索引，索引失败则恢复文件。删除确认提示明确说明永久删除，不能当作回收站。

临时清理主要针对本次创建的临时文件、安装解包目录和 LiveStudio 事务目录。恢复本身会重建目标滤镜并写入直播应用配置，也会停止/启动相关进程；这属于恢复操作，不能将“删除存档不改直播配置”推广为所有功能都不改配置。开播状态当前不阻断恢复，直播期间误操作可能中断直播。

本次是有界代码审查，不是对所有文件系统重解析点、损坏事务日志、磁盘故障或进程竞态的形式化证明。

## 安装版空闲短时采样

24 个逻辑处理器，两个安装版进程约 30 秒的 7 次采样：

- Agent 工作集 249.8–281.0 MiB，私有内存 167.6–199.4 MiB，累计 CPU 增加 0.921875 秒。
- Desktop 工作集 278.9 MiB，私有内存 245.4 MiB，累计 CPU 增加 0.015625 秒。
- 合计工作集约 528.7–559.9 MiB，按全机逻辑处理器归一化的平均 CPU 约 0.13%。
- GPU Engine 计数器对 Desktop 的 3 次短时采样显示各引擎约 0.00%；未取得 Agent GPU 引擎条目，不能据此替代开播负载测试。

短时采样未出现持续内存增长，不能证明长时间无泄漏，也不证明另一台直播主机的编码帧率。

## 隔离导出负载

使用现有 2026-09-10 存档，在独立进程执行正式 SnapshotPackageReader 与 SnapshotParameterWorkbook，导出至忽略目录。用时 2.64 秒，峰值工作集 392.8 MiB，采样峰值私有内存 371.7 MiB，退出码 0。该值是独立导出进程峰值，不是安装版 Agent 的实测增量，也不能机械加到空闲数据上。

代码仍在内存中展开包内文件、参数树和 Excel XML；大素材和大量字段可能引起更高的内存及 CPU 峰值。

## 后台负载与部署判断

- 云端注册后，Agent 每 20 秒心跳会 CaptureAsync 读取参数；心跳不会生成截图。明确刷新预览、保存或恢复后的发布路径会请求截图。
- 配置局域网共享后，每 15 秒轮询；当前 PublishAsync 即使共享目录已有相同存档，也会重新计算源哈希、完整检查源包，再计算目标哈希。存档多或网络盘慢时会产生重复磁盘/网络和解析负载。
- 已注册云端的 Agent 会接收并执行授权的远程任务，不能把“本机未点击按钮”视作绝不会开始操作。

结论：当前未发现普通空闲状态持续占满 CPU/GPU 的现象，也未发现全盘清理代码；但不能承诺 v0.1.29 在高负载直播过程中保存、导出、同步或恢复完全无影响。部署后宜在开播前完成保存与恢复核对；不需要的同步功能保持未配置，直播时不要执行恢复。大包内存峰值、局域网重复校验与云端心跳的读取频率仍值得后续优化。本轮没有发布新版本。
