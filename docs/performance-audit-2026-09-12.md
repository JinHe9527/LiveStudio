# 2026-09-12 桌面存档切换与发布体积优化

> 后续已按使用者要求发布 v0.1.28，正式发布与公开安装器验证见 `windows-validation-handoff.md` 第 50 节。下文体积与性能数据保留为发布前检查记录。

本轮仅调整桌面读取与展示、Release 发布文件筛选，没有生成安装器、安装新版本、写入 OBS/直播伴侣或执行恢复。

## 体积

本机已安装 0.1.26 的 Desktop 目录约 206.4 MiB，Agent 约 199.4 MiB。Desktop 中 `libSkiaSharp.pdb` 为 80.14 MiB，`libHarfBuzzSharp.pdb` 为 19.95 MiB；这些是调试符号，不是运行库。

`Directory.Build.targets` 在 Release 的 `ComputeFilesToPublish` 后排除 PDB，构建目录继续保留符号。实际对 Desktop 和 Agent 执行 win-x64 自包含 publish 后，目录分别为 106.01 MiB 和 199.17 MiB，PDB 数量为 0。合计发布载荷约 305.18 MiB，相比已安装目录约减少 100 MiB。未生成新 MSIX 或 Setup，不能将目录减少量直接表述为压缩安装包减少量，也没有替换本机安装版。

本机验证目录：`artifacts/performance-audit/publish-desktop`、`publish-agent`。运行库和内置素材没有裁剪；重复运行库合并及 AOT/trimming 不属于本轮交付。

## 存档切换

原实现串行等待当前存档、参考图、上一份存档比较，再显示参数，并继续请求两款应用预览。比较结果和应用预览在当前首页没有绑定。真实本机三份存档的独立探针测得：详情读取 275–424 ms，显示投影 236–342 ms；这些是单次样本，不是跨设备统计。

修改后：

- 切换立即更新选中项和标题，60 ms 合并快速连续选择，只读取最后选择项。
- CPU 密集的参数投影在后台构建；取消或选择对象改变后不发布旧结果。
- 不再请求当前首页未显示的上一份比较和应用预览。
- 最近三份无参考图的存档缓存显示模型；按列表对象身份命中，刷新执行端状态和断开时清空。机位编辑使对应缓存失效，避免重新进入时重放未保存参数。
- 有参考图的存档不纳入缓存，继续完成参考图与保存路径绑定后显示，避免增加图片内存及影响后续联合保存。
- 缓存只参与展示；导出、保存、恢复仍走原本执行端协议和包校验。
- 恢复应用选中项，处理 ListBox 双向绑定在数据源切换时暂时清空选择的问题。

本机 Release ViewModel 探针（不包括 UI 布局/屏幕绘制）测得：首次 758.95 ms，另一份首次 571.43 ms，返回缓存项 0.2083 ms。不能将缓存数据准备耗时宣称为完整点击到像素更新的零延迟。开发窗口实际检查了首次显示、切换另一份、返回缓存项，参数可见且标题匹配。

首次读取及含参考图的存档仍有等待；本轮没有移除签名、哈希或执行端回读校验。
