## 2026-09-13 取消、授权关闭与事务清理加固

继续保留既有权限不足时通过 Windows 系统 taskkill 的 runas 授权关闭路径，并在恢复进度中提前说明管理员授权。关闭命令一旦发出，等待退出不再受调用方取消影响，避免回滚与仍执行中的关闭操作竞争；发出命令前仍尊重取消。授权工具返回成功也会重新检查目标进程是否已退出。此改动不代表已实现任意配置文件 ACL 的自动修复，未修改任何文件权限。

修复事务资源清理的失败传播：一个会话或运行状态清理抛错后继续处理其余应用；已经逐字段核对并持久提交的参数不因清理失败反向回滚，结果保留成功状态并明确附带应用运行状态警告。未提交情况下若清理失败则返回 RollbackFailed，不能继续声称原状态完整恢复。新协议的可选 Warning 将清理警告传至首页，避免只显示普通成功文案。

回滚完成后的进度通知失败不再遮蔽真实结果。去除底层进程关闭错误中无条件“配置没有写入”的表述，因为同一关闭函数也可能在回滚阶段调用。

新增故障注入覆盖提交后与提交前的会话/运行状态清理双重失败、继续释放另一款应用，以及回滚后的进度通道断开。整仓 Release 构建 0 警告、0 错误，384 项测试通过（Core 325、Agent 51、Setup 8），依赖无已知漏洞。本轮没有触发实际 UAC、停止生产应用或执行真实恢复，不能将模拟测试当作实际授权/驱动/跨电脑验收，Verified 仍为 0。

## 2026-09-13 Excel 手动恢复工作簿与保存入口素材核验

按使用者最新要求采用 `.xlsx`，不生成 TXT。正式产品通过 .NET 内置 ZIP/XML 生成 OOXML，不依赖目标电脑安装 Excel 或开发环境的表格运行时。每次新建或重新签名存档生成包内 `parameters.xlsx`，纳入清单哈希和签名；重新签名时重新生成，避免相机备注更新后工作簿陈旧。原格式与旧包读取保持兼容。

本地导出同时输出同名 `.xlsx`，既有同名存档或 Excel 拒绝覆盖；文字说明失败时清理本次新建导出包，原存档保持不变。云端导出也生成 Excel，附件失败明确显示已经导出的存档位置及附件失败原因。旧存档导出时可从已验证的参数生成 Excel，不需重签名原包。

工作簿提供恢复指南、每个应用的参数、素材清单和完整字段。参数页使用深色表头、交替行底色、冻结表头、筛选及手动核对下拉框；已核对与无法设置由条件格式区分。完整字段页逐叶展开全部已存参数，保留路径、类型、空容器、空值、精确数值文本和数组索引；长字符串按安全字符边界分段，不受 Excel 单元格字数上限截断，公式样式字符串始终写作文本。所有原数据在生成前仍执行敏感字段扫描。

保存包入口新增素材闭合验证：每个声明的文件必须存在且长度、类型、SHA-256 一致，每个素材绑定必须指向对应内容；缺失或损坏时不能生成看似完整的存档。这里尚未实现第三方插件程序本体打包、自动安装以及通用权限修复。更大的“完整软件依赖恢复”目标仍未完成，不能把本节描述为该目标已经交付。
