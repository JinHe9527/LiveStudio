## 已修复的问题

| 优先级 | 问题 | 修复与验证 |
| --- | --- | --- |
| P1 | 坏签名 PEM 或空签名可能使 Agent 启动扫描失败，正常存档也不可用。 | 拒绝空签名，将解析异常统一为存档错误并释放密钥；损坏文件保留、健康文件继续索引的回归通过。 |
| P1 | 删除最后一个摄像头后，扫描丢弃空容器，目标匹配和恢复前备份阻断来源重建。 | 保留真实空容器结构证据；独立恢复前稳定备份入口，不完整配置只能作为只读备份。真实删除重建与完整回读通过；7 阶段失败均恢复 5 份原生事务文件的原字节，备份生成且无残留。回归确认未收集非摄像头来源和布局。 |
| P1 | 可移植预检未核对驱动模式，旧无效模式可能写入后被原生应用改掉。 | 独立限时子进程只读枚举 DirectShow，要求唯一设备匹配、分辨率/粒度、帧率和像素格式匹配；未知格式拒绝，不调用 SetFormat。新增签名版本边界、现有参数类型冲突及已确认色彩枚举检查。 |
| P1 | 小数帧率经四舍五入变为整数。 | 精确保留有理数，例如 29.97 → 2997/100；非法值和不支持精度不猜测。回归通过。 |
| P1 | 空素材可保存，却无法恢复。 | OBS 与直播伴侣均在捕获空素材时失败；两款适配器回归通过。 |
| P1 | Release 前置 dotnet 失败可能被后续退出码掩盖；漏洞列表未实际阻断发布。 | 各质量门独立检查退出码；漏洞 JSON 包含漏洞、服务错误、非法报告、空项目均失败。6 项脚本回归和真实 15 项目查询通过。 |
| P2 | Setup 版本可能与 MSIX 不一致。 | 从 MSIX manifest 读取四段版本并传入安装器发布，最终签名产物另行核对。 |

设备能力实现依据 Microsoft 的 [IAMStreamConfig.GetStreamCaps](https://learn.microsoft.com/en-us/windows/win32/api/strmif/nf-strmif-iamstreamconfig-getstreamcaps) 和 [VIDEO_STREAM_CONFIG_CAPS](https://learn.microsoft.com/en-us/windows/win32/api/strmif/ns-strmif-video_stream_config_caps)。数值像素格式与色彩枚举取自本机 12.9.2 原生 MediaSDK 定义；没有猜测未映射格式为支持。

## 真机结果

1. 原关闭状态文件保存 2160×3840、60 FPS、YUY2。驱动检查拒绝，Agent 写入前阻断；原生应用启动后自行归一为 1920×1080、30 FPS、NV12。设置界面与稳定保存值一致。旧模式值不能当作硬件支持证据，原始备份保留。
2. 以原生支持的模式保存新存档，正式 Agent 恢复及逐字段回读通过，无事务残留。
3. 备份后删除摄像头，依次注入 SessionsCreated、ApplicationsStopped、AssetsPrepared、SettingsApplied、ApplicationsStarted、VerificationPassed、ApplicationsCommitted 故障：**7/7** 返回已回滚失败、创建永久备份、5 份原生边界文件逐字节一致、事务残留 0。
4. 关闭故障注入后，真实删除摄像头的正常重建成功，完整回读通过，事务残留 0。
5. SettingsApplied 强制终止 Agent 后启动回滚至原字节；DurableCommitRecorded 强制终止后启动保留已提交字节并清理事务。**2/2** 通过，Agent 重新可恢复，无残留。
