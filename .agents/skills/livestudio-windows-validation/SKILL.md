# LiveStudio Windows 真机验收

## 开始工作

1. 完整阅读仓库根目录的 `AGENTS.md`。
2. 完整阅读 `../../../docs/windows-validation-handoff.md`，以其中的当前能力、流程和完成门槛为准。
3. 执行仓库状态检查，确认当前分支、最新 commit 和未提交改动。
4. 记录测试机、Windows、OBS、直播伴侣、采集卡和驱动的精确版本；缺少这些信息时，结论只能归入未验证证据。

## 选择工作模式

- 用户提供修改前/修改后原生导出包时，执行“原生导出差异实验”。一次只接受一个参数变化，先检查敏感路径，再核对变化字段。
- 用户需要寻找真实配置位置时，执行“存储探测实验”，覆盖 File、Registry、SQLite、LevelDB、进程退出落盘和必要的 IPC 观察。
- 用户要求生成适配器时，先核对字段矩阵是否完整。只有每个目标字段都有原生路径、类型、读写和回读证据，才实现并签名适配定义。
- 用户要求验证恢复时，先执行全部 Preflight，再按事务快照、停止应用、应用、启动、逐字段回读、Commit/Rollback 的顺序运行。
- 用户只提供截图或口头描述时，先登记为线索，不能据此生成可写适配器或宣称覆盖完成。

## 参数完整性规则

目标不是“保存常用参数”，而是证明目标范围内没有遗漏。必须覆盖：

- 设备与视频模式的全部可选字段。
- OBS 全部视频来源设置及全部视频滤镜的 kind、启用状态、顺序、嵌套参数和素材。
- 直播伴侣全部美颜、塑形、美妆、预设、素材和内部引用。
- Master、R、G、B 曲线的全部控制点、顺序、坐标类型及插值相关字段。
- 对象、数组、空值、默认值、当前值和未知但位于目标配置树内的字段。

音频、场景布局、账号、登录态、Cookie、Token、推流密钥和 HDMI 上游相机机身参数不进入存档。

## 判定规则

- 原生导出能导入，不代表它包含全部目标字段。
- 参数改变但原生导出无差异，立即将该字段标记为“原生导出未覆盖”，继续寻找其他持久化位置。
- 变化超过一个业务字段时，本轮证据作废并重做单变量实验。
- 缺少签名适配定义时禁止正式写入；不得让实验扫描结果进入恢复路径。
- 任一字段回读不一致都必须回滚；不得接受近似值、默认值或静默跳过。
- 只有完成两台不同采集卡电脑、至少 20 次连续循环且目标状态和原状态回滚均逐字段 100% 一致，才标记“已验证”。

## 证据和输出

按 `references/evidence-schema.md` 记录证据。原始 ZIP 或配置文件默认只留在隔离测试机；先生成不含原始值的结构/差异报告，完成敏感字段审计后才能决定是否制作脱敏 fixture。

交付结论必须分别列出：

- 已证明覆盖的字段。
- 未覆盖或证据不足的字段。
- 敏感数据风险。
- 当前是否允许只读、实验恢复或正式恢复。
- 下一步最小实验，不得用开发计划掩盖缺失证据。
